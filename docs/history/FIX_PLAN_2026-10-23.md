## P0 — bắt buộc trước khi dùng thật

### P0-1. Secret proxy phải gắn với đúng proxy identity

- Thêm `ProxyConfig.identity_key()` gồm protocol + host + port + username.
- Lưu `proxy_identity` cùng password trong `secrets.dpapi`.
- `get_proxy_password(profile_id, identity=...)` trả `None` nếu identity không khớp.
- Khi update proxy:
  - Nếu identity đổi và password để trống → xóa secret cũ, không tái sử dụng.
  - Nếu identity không đổi và password để trống/redacted → dùng secret cũ.
  - Nếu có password mới → ghi secret mới kèm identity mới.
- API update dùng cùng logic identity, không chỉ host/port/username.

**Test:** đổi `1.2.3.4:8080` → `5.6.7.8:9090` với password trống phải trả `None`;
đổi cùng endpoint phải giữ password; `profiles.json` không có plaintext.

### P0-2. Xóa profile đúng thứ tự, không làm mất secret

- Xóa thư mục profile trước.
- Nếu xóa thư mục thất bại → giữ nguyên metadata và secret, trả lỗi rõ ràng.
- Chỉ xóa metadata sau khi thư mục đã xóa.
- Chỉ xóa secret sau khi metadata đã lưu thành công.
- Thay `print()` bằng logger an toàn UTF-8, không crash trên console cp1252.
- API trả 409 khi thư mục bị khóa; 404 chỉ khi profile không tồn tại.

**Test:** mock `shutil.rmtree` lỗi → metadata và secret còn nguyên; xóa lại thành công
thì secret mới bị xóa.

### P0-3. Single-instance OTC phải do server đang chạy cấp

- Instance thứ hai không được import `web.app` để tự sinh OTC.
- Đọc `access_key` từ `runtime.dpapi`, gọi `POST /auth/create-unlock-code`.
- Chỉ fallback tạo OTC cục bộ khi chính process này là server.
- Nếu không lấy được OTC, mở `/unlock` không kèm code thay vì tạo code vô dụng.

**Test:** giả lập server trả OTC qua HTTP; instance thứ hai nhận đúng code.
Khi HTTP lỗi và `allow_local=False`, không sinh code cục bộ.

### P0-4. Persist trạng thái launch và dùng đúng DevTools port

- Thêm `browser_runtime.json` ghi atomic: `profile_id`, `pid`, `port`,
  `requested_port`, `user_data_dir`, `exe`, `started_at`, `created`.
- `BrowserLauncher` load file khi khởi động; `is_running()` xác minh lại process
  bằng `read_browser_identity()` trước khi tin.
- `stop()` và `stop_all()` dùng runtime state để dừng browser sau khi server restart.
- `_setup_cdp_stealth()` cập nhật `active_ports` và runtime state bằng
  `DevToolsActivePort` thật.
- `launch()` trả port thật, không chỉ port dự kiến.
- Reserve port trong process để giảm race giữa hai launch đồng thời.

**Test:** ghi runtime state giả + mock identity owned → `is_running()` true và
`active_ports` đúng; xóa state khi stop; port reserved không bị cấp lại.

### P0-5. Xác minh server identity trước khi kill

- Lưu `cmdline_digest`, `process_created` trong `server.pid`.
- `verify_server_identity()` kiểm tra:
  - exe là Python;
  - command line chứa `run.py`;
  - digest command line khớp;
  - creation time khớp (nếu có).
- `stop_server()` không fallback `taskkill /F` khi API shutdown trả 409
  (còn profile đang chạy).
- Chỉ xóa `server.pid` sau khi xác nhận process đã chết.
- `stop.bat` dừng nếu `cli.py stop-all` thất bại, không kill server để tránh orphan.

**Test:** command line/digest sai → verify false; health 409 → không gọi taskkill;
verify true + process chết → xóa PID file.

### P0-6. Lock fail-closed và secret store chống ghi đè

- `InterProcessLock` hết timeout phải raise `TimeoutError`, không tiếp tục không lock.
- `secrets.dpapi` hỏng:
  - backup file lỗi;
  - `get` trả `None` an toàn;
  - `set/delete` raise `SecretStoreCorruption`, không ghi đè;
  - `save_profiles` chỉ tiếp tục nếu không có plaintext password cần migrate.
- Thêm test corrupt file: bytes gốc không đổi, có backup, set bị chặn.

## P1 — quan trọng, làm trong cùng đợt nếu không rủi ro

### P1-1. WebRTC flags theo mode và proxy

- Không luôn thêm `--force-webrtc-ip-handling-policy`.
- Chỉ thêm flag khi proxy bật và mode là `block`/`disable_non_proxied`.
- Mode `auto` không ép flag.
- Giữ JS hook `RTCPeerConnection` tương ứng mode.

### P1-2. Bỏ cờ WebGPU sai

- Không thêm `--disable-features=WebGPU` chỉ vì profile giả lập macOS/Linux.
- WebGPU thật được che bằng hook `navigator.gpu` hiện có.
- Ghi rõ giới hạn features/limits vẫn là host.

### P1-3. Edge/Chrome brand nhất quán

- Thêm `browser_brand` (`chrome`/`edge`/`chromium`).
- `normalize_fingerprint_for_launch()` phát hiện brand từ đường dẫn browser.
- UA, Client Hints brands và `fullVersionList` khớp brand thực tế.
- Nếu chỉ có Edge, không còn cảnh "Edge chạy với UA Chrome".

### P1-4. Locale/Timezone theo GeoIP

- Thêm mapping country → locale BCP-47.
- Khi tạo/reset fingerprint có proxy, dùng locale từ GeoIP thay vì luôn `vi-VN`.
- Thêm `--accept-lang` và giữ CDP `acceptLanguage`.
- Thêm `tzdata` vào `requirements.txt` cho Windows sạch.

### P1-5. CDP verify mở rộng

- Kiểm tra thêm timezone, WebGL vendor/renderer, Client Hints brands/platform,
  languages, deviceMemory, colorDepth.
- Trả về chi tiết check trong kết quả launch (`verification`).
- Chỉ coi `configuration_verified=true` khi tất cả check cốt lõi pass.

### P1-6. Prototype constructor và WebGL canvas

- Sửa `Worker.prototype.constructor` và `RTCPeerConnection.prototype.constructor`
  trỏ đúng wrapper sau khi hook.
- Thêm đường `HTMLCanvasElement.toDataURL()` cho WebGL: đọc pixel, thêm noise
  deterministic, trả ảnh từ canvas 2D tạm. Có fallback native nếu đọc lỗi.
- Ghi rõ canvas 2D chỉ noise pixel alpha=255 để giữ nhất quán
  `toDataURL()`/`getImageData()`.

### P1-7. Dashboard self-host asset + CSP

- Vendor `tailwind.js` và `lucide.min.js` vào `web/static/vendor/`.
- Mount `/static` trong FastAPI.
- Bỏ script CDN khỏi `index.html` và CSP.
- Giữ `unsafe-inline` tạm thời vì template còn inline handler; ghi rõ đây là nợ kỹ thuật.

### P1-8. Audit WebGL có ý nghĩa

- Audit vẽ WebGL thật (clear color + readPixels), hash pixel thay vì hash canvas trắng.
- Thêm cảnh báo collision `webglPixelHash` giữa các profile.
- Không coi 41/41 là "an toàn" nếu có collision.
